```bash

  -m 'deepseek/deepseek-flash#repo-scout' \
```

The first attempt used absolute `read`/`glob`/`grep` permission resources and was

## CLI cancel

SIGTERM and SIGKILL to the `opencode run` process group both left no CLI or private
server process. OpenCode starts the private `serve --stdio` child in its own process
group, but it exits when the parent is terminated.

## API runner

The server requires HTTP Basic auth as `opencode:<password>`. Start it with a known
password via `OPENCODE_PASSWORD`:

```bash
OPENCODE_PASSWORD='<secret>' opencode serve --hostname 127.0.0.1 --port 4199
```

Result: **pass**, 135 s. Session outcome `succeeded`. Because `docs/` already existed
from the CLI run, the skill correctly wrote:

- `repo/docs/gist/codemap.md`
- `repo/docs/gist/routing.md`
- `repo/docs/gist/observation.md`

`POST /api/session/{id}/interrupt?resume=false` returned
`{"interrupted": true}` and the session became idle with outcome `interrupted`.

## API password decision

`opencode serve` does not accept an unauthenticated client. Add:

- `OPENCODE_API_PASSWORD` to the bot env.
- `OPENCODE_PASSWORD` to the dedicated API server env.
- HTTP Basic auth username `opencode` in the Go client.
- `scripts/m0-setup.sh` generates a shared random password into both env files.
